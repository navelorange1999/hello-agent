# Project: Embedding 实验场

## 为什么做这个项目？

Embedding 是连接"自然语言"和"数学计算"的桥梁。理解 Embedding，你就理解了 Agent 是怎么"理解"和"检索"知识的。这个项目让你从直觉层面把握向量语义。

---

## 项目目标

构建一个 Embedding 探索和可视化工具：

1. 使用 Embedding API 将文本转化为向量
2. 实现并对比多种相似度计算方法
3. 用降维可视化揭示文本的语义关系
4. 探索 Embedding 的边界和局限

---

## 任务拆解

### Task 1：Embedding 初体验（Day 1）

- [ ] 使用 OpenAI Embedding API（`text-embedding-3-small`）将 10 个句子转为向量
- [ ] 打印向量的维度和前 10 个分量，感受一下"向量"长什么样
- [ ] 计算任意两个句子之间的余弦相似度
- [ ] 准备一组有趣的测试对：同义句对、反义句对、不相关句对
- [ ] **笔记**：你觉得"国王"和"皇帝"的向量距离更近，还是"国王"和"苹果"更近？实测验证

### Task 2：相似度计算与排序（Day 1-2）

- [ ] 实现三种距离度量：余弦相似度、欧氏距离、点积
- [ ] 给定一个 query 句子和 50 个候选句子，分别用三种方法排序，对比 Top 5 结果
- [ ] 测试边界情况：空字符串、超长文本、纯数字、混合语言
- [ ] **思考**：为什么大多数向量数据库默认使用余弦相似度？什么场景下欧氏距离更合适？

### Task 3：向量空间可视化（Day 2-3）

- [ ] 用 PCA 或 t-SNE 将高维 Embedding 降到 2D
- [ ] 用 matplotlib 绘制散点图，标注每个点对应的文本
- [ ] 准备 3-4 个类别的句子（如：科技新闻、体育新闻、美食评论、旅游攻略），观察它们在向量空间中是否自然聚类
- [ ] 做一个有趣的实验：把中文和英文的同义句都画在同一个图上，看看它们的位置关系
- [ ] **延伸**：用 `plotly` 做交互式 3D 可视化

### Task 4：Embedding 模型对比（Day 3-4）

- [ ] 对比不同 Embedding 模型的效果（OpenAI vs 开源 sentence-transformers）
- [ ] 在同一个检索任务上评估：Recall@5, Recall@10
- [ ] 测试 Embedding 的局限：否定句（"这家餐厅不好吃" vs "这家餐厅好吃"的相似度）
- [ ] 测试跨语言能力：英文 query 能检索到对应的中文文档吗？
- [ ] **笔记**：总结不同 Embedding 模型的选型建议

## 验收标准

- [ ] 能快速计算任意两段文本的语义相似度
- [ ] 生成至少 2 张有洞察力的向量空间可视化图
- [ ] 能说出 Embedding 的至少 3 个局限性
- [ ] 能向别人解释：Embedding 在 Agent 系统中扮演什么角色？

## 延伸思考

> 在 RAG 系统中，用户的 query 会被 embed 成向量，然后在知识库中检索最相似的文档片段。但 query 通常很短（"怎么退货？"），文档片段通常很长（一整段退货政策）。短文本和长文本的 Embedding 效果一样好吗？怎么优化？
