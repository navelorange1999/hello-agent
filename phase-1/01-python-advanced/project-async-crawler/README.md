# Project: 异步网页爬虫

## 为什么做这个项目？

AI Agent 的核心能力之一是**并发调用多个工具**（同时搜索网页、查数据库、调 API）。这背后就是 Python 的 async/await 机制。通过构建一个异步爬虫，你会深刻理解事件循环、协程调度和并发控制——这些是后面写 Agent 的地基。

---

## 项目目标

构建一个异步网页爬虫，能够：

1. 从一个种子 URL 出发，并发抓取页面内容
2. 解析页面中的链接，递归爬取（控制深度）
3. 用信号量（Semaphore）控制并发数，避免压垮目标服务器
4. 将结果异步写入本地文件

---

## 任务拆解

### Task 1：理解事件循环（Day 1）

- [ ] 手动创建一个事件循环，运行 3 个简单的协程
- [ ] 用 `asyncio.gather` 并发执行，观察输出顺序
- [ ] 对比 `asyncio.gather` vs `asyncio.create_task` vs `await` 的行为差异
- [ ] **笔记**：画出事件循环调度协程的时序图

### Task 2：异步 HTTP 请求（Day 1-2）

- [ ] 安装并使用 `aiohttp` 发起异步 GET 请求
- [ ] 实现一个函数：输入 URL 列表，并发请求所有 URL，返回结果
- [ ] 加入 `asyncio.Semaphore` 控制并发上限为 5
- [ ] 处理超时和异常（某个请求失败不影响其他请求）
- [ ] **思考**：为什么要用信号量？直接 gather 1000 个请求会怎样？

### Task 3：链接解析与递归爬取（Day 2-3）

- [ ] 用 `BeautifulSoup` 或正则从 HTML 中提取所有链接
- [ ] 实现 BFS 爬取逻辑：维护一个 visited 集合，避免重复
- [ ] 加入深度限制（max_depth=2）
- [ ] **思考**：为什么用 BFS 而不是 DFS？在 Agent 的工具调用中，这种策略有什么映射？

### Task 4：异步文件写入与整合（Day 3-4）

- [ ] 使用 `aiofiles` 将爬取结果异步写入 JSON 文件
- [ ] 实现优雅退出：捕获 KeyboardInterrupt，保存已爬取的数据
- [ ] 添加简单的进度日志输出
- [ ] **笔记**：总结 async 编程中常见的坑（忘记 await、阻塞调用混入异步等）

---

## 验收标准

- [ ] 能从一个种子 URL 开始，2 层深度内并发爬取 50+ 页面
- [ ] 并发数可控，不会因为请求过多导致报错
- [ ] 单个请求失败不影响整体流程
- [ ] 能清晰地向别人解释：事件循环是如何调度你的协程的
